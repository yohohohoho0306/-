## 減らし方

1. **続けて通過した銘柄は、新しい有報が出るまで調べ直さない**：`prepare_verify.py --only-new` がそうする。銘柄ノートと `research/data/<日付>/verify.json`・`labels.json` に前回の調査が残っている。
2. **確認済みの不通過銘柄は確かめ直さない**：`prepare_verify.py --skip-checked research/data/*/checked.json`。
3. **キャッシュを残す**：`.cache/edinet`（約34MB・約5,800ファイル）は作業環境が消えると一緒に消える。古い書類一覧と4〜5年前の有報は変わらないので、残しておけば判定だけの回のダウンロードがかなり減る（年1回の全面更新では効果が小さい）。残し方は次のどれか（どれもまだ設定していない）。
   - GitHub Actions のキャッシュ（判定を Actions で回す場合）
   - GitHub の Release に圧縮ファイルとして置く
   - リポジトリにコミットする（履歴が重くなる）
4. **判定だけなら Claude を使わない**：`run_all.py` は GitHub Actions などで定期実行できる（EDINET_API_KEY を GitHub のシークレットに入れる）。Claude は差分を読んで調べるときだけ使う。
5. **Web 検索より有報の原本**：Web 検索はセッション全体で 200 回の上限があり、2026-10-13 は途中で上限に達した。テーマ性・配当方針は有報（EDINET の PDF）でほぼ確かめられた。
