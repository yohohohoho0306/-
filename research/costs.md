# 費用と時間の目安

## 2026-10-13 にかかったもの

初回だったので、スクリプトを実データで初めて動かし、不具合を直しながら進めた。次回は大部分が要らなくなる。

| 作業 | 量（2026-10-13） | 次回 |
|---|---|---|
| 不具合の調査と修正（22件）、レポートの作成（本体の会話） | モデルの呼び出し 約420回。入力の読み込み（キャッシュを含む）約1.4億トークン | 不具合の調査はほぼ不要。新しい種類の分割など、見たことのない例が出たときだけ |
| エージェントによる確認 | 37体・呼び出し 約1,270回。入力の読み込み 約1.4億トークン | 新しく通過した銘柄と、判定が変わりうる不通過の銘柄だけ |
| 　うち通過銘柄の調査・反証の点検、不通過22銘柄の確認 | 27体・約1,090回（1銘柄あたり 約13回・約150万トークン） | 同上 |
| 　うち試し実行8銘柄の突き合わせ | 10体・約180回 | 不要（突き合わせは済んだ） |
| 有報・株価のダウンロード | 約1〜1.5時間（EDINET の書類一覧 約460日分、有報 約4,300通、株価 約3,800銘柄） | キャッシュがあれば不要 |
| 全社の判定（キャッシュあり） | 75秒 | 同じ |

- 呼び出し回数とトークンは、この作業環境の会話記録から数えた値。利用料金の額はこの環境からは分からない。
- 作業の時計の時間は、利用制限による中断と待ち時間を含むので目安にならない。
- Web 検索はセッション全体で 200 回の上限に達し、途中から有報の原本（EDINET の PDF）で確かめる方法に切り替えた。

## 次回の見込み

| やること | Claude の消費 | 時間 |
|---|---|---|
| 判定だけ（月1回〜四半期に1回） | 少ない（コマンドの実行と差分の確認。今回の数%） | キャッシュあり 数分、なし 約1〜1.5時間 |
| 年1回の全面更新 | 新しく通過した銘柄 N 件について 約13回×N の呼び出しと、判定が変わりうる不通過の確認、レポートの文章の手直し | 判定と同じ＋確認に数十分〜 |
| このノート群を読む | 入口・次回の進め方・費用・既知の問題で 1万トークン前後。銘柄ノート全部で 10万トークン前後、レポート全体で 5万トークン前後（目安） | — |

ノートを読む量は、調べ直しを省ける量に比べて小さい。全部を読む必要はなく、入口と次回の進め方から、要る銘柄ノートだけを開けばよい。

## 減らし方

1. **続けて通過した銘柄は調べ直さない**：銘柄ノートと `research/data/<日付>/verify.json`・`labels.json` に前回の調査が残っている。新しい有報が出た銘柄の配当政策だけ確かめる（[次回の進め方](next-run.md) の 5）。
2. **キャッシュを残す**：`.cache/edinet`（約34MB）は作業環境が消えると一緒に消える。古い有報の値は変わらないので、残しておけば次回のダウンロードは新しい有報と株価だけになる。残し方は次のどれか（どれもまだ設定していない）。
   - GitHub Actions のキャッシュ（判定を Actions で回す場合）
   - GitHub の Release に圧縮ファイルとして置く
   - リポジトリにコミットする（約34MB・4,300ファイル。履歴が重くなる）
3. **判定だけなら Claude を使わない**：`run_all.py` は GitHub Actions などで定期実行できる（EDINET_API_KEY を GitHub のシークレットに入れる）。Claude は差分を読んで調べるときだけ使う。
4. **Web 検索より有報の原本**：検索は上限がある。テーマ性・配当方針は有報（EDINET の PDF）でほぼ確かめられた。
